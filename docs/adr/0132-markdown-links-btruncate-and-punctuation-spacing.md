# ADR 0132：Markdown超链接批量转换提取、UTF-8字节边界安全截断宏与中英标点空格排版规整 (Markdown Links Conversion, Byte Truncate Macro & Punctuation Spacing)

## 状态
已接受，T-0460~T-0464（2026-10-29）。

## 背景与上下文
在思源笔记常用内容资产的跨源收集、富文本导出与中英文案精细排版场景中，存在三类高频实用痛点：
1. **Markdown 超链接格式批量提取与形态转换**：
   从网页、公众号或 Markdown 剪贴板中复制的大段内容，常常包含大量 `[文本](URL)` 超链接。用户需要便捷提取其中的裸 URL 清单（以便批量下载或转存），或剥离超链接保留纯文本标题（用于报告净化），或反向将裸 URL 批量转换并包裹为自动命名的 Markdown 链接；
2. **UTF-8 字节长度安全边界截断引擎与 `{{xlc:btruncate}}` 动态宏**：
   在对接外部数据库（如 VARCHAR(255) 字段）、短信字数上限或特定通信协议时，字符限制通常以 UTF-8 字节（Byte）而非字符数（Char）进行硬性约束。如果对中文字符粗暴切片，容易将 3 字节或 4 字节的 UTF-8 码元中途劈开，造成严重的  乱码甚至字符损坏。需要纯函数精准按 UTF-8 码位（Code Point）边界执行安全截断并支持优雅省略号；
3. **中英混排标点间距与全半角空白规范化排版**：
   根据排版美学与中文排版准则，中文全角标点（，。！？；：、“”‘’《》）前后绝不应出现多余的空格（如 `你好 ， 世界`）；而英文字母后跟随半角标点并接续英文单词时，则必须规范留出一个半角空格（如 `hello,world` 必须规整为 `hello, world`），同时严格保护数值小数（`3.14`）和 URL 路径。

## 决策与落地
1. **Markdown 超链接批量转换与提取引擎 (`convertMarkdownLinks`)**：
   - 纯函数实现，支持 `strip`（剥离链接）、`text_and_url`（标题加括号URL）、`bare_url`（纯URL）以及 `auto_markdown`（裸URL自动加方括号包裹）4 种模式；
   - 动作菜单接线「🔗 提取所有 Markdown 链接 URL 并复制」与「🔗 剥离链接保留纯文本标题并复制」，表单格式栏接入「✦ 剥离超链接」。
2. **文本字符与 UTF-8 字节长度安全截断引擎 (`truncateByBytes`) 与 `{{xlc:btruncate}}` 动态宏**：
   - 纯函数实现，严格依据 UTF-8 编码规则（ASCII 1字节，拉丁 2字节，汉字 3字节，Emoji 4字节）在代码点安全边界停止累加；
   - 扩展动态宏体系 `{{xlc:btruncate|10|你好世界}}`、`{{xlc:btruncate:10|你好世界}}`、`{{xlc:btruncate:10|...|你好世界}}`；
   - 动作菜单接线「✂ 截断至 255 字节上限 (防超长截断) 并复制」，表单格式栏接入「✦ 255字节截断」，表单变量栏补充 `{{xlc:btruncate|100|长文本}}`。
3. **中英混排标点间距与中英空隙智能规整引擎 (`formatPunctuationSpacing`)**：
   - 纯函数实现，自动剔除中文全角标点前后异常空格，并在英文字母与英文标点后智能补齐标准半角空格；
   - 动作菜单接线「🔤 规整中英标点空格排版并复制」，表单格式栏接入「✦ 标点空格规整」。
4. **自动化门禁与双向严格负向验证**：
   - 新增 `tests/r358-linkconvert-btruncate-and-punctspace.test.cjs` 专项测试；
   - 负向突变 95 破坏字节截断输出，负向突变 96 破坏标点空格清理，两项负向测试均被精确拦截；
   - 源码恢复后复验全绿通过，单元测试总数达到 952/952 项。
