# ADR 0128：Markdown表格列对齐批量转换、定长字段补齐截断宏与行尾NBSP隐形空格深度清洗 (Table Alignment, Pad/Truncate Macro & Line Endings Sanitization)

## 状态
已接受，T-0440~T-0444（2026-10-29）。

## 背景与上下文
在思源笔记常用内容库的实际使用与文本编辑流转场景中，存在三类高频实用痛点：
1. **Markdown 表格列对齐方式批量转换**：
   从其他工具粘贴或编辑而来的 Markdown 表格，分隔线行（`| --- | --- |`）常常默认左对齐或没有显式对齐指示符。在报表、财务明细或对比清单中，用户需要批量将全部列设为居中对齐（`:---:`）、右对齐（`---:`，适合数值与金额）或分别指定各列对齐，而无需手动逐列修改冒号；
2. **文本字段定长补齐截断引擎与 `{{xlc:pad}}` 动态宏**：
   在输出对齐清单、单号补前导零（如 `000042`）或限制特定摘要字段最大展示宽度时，用户需要纯函数根据目标视觉宽度（支持 CJK 中文字符双倍视觉宽度）自动左补齐、右补齐、居中补齐或超出截断（支持省略号）；
3. **多行文本行尾空格与 NBSP 不换行隐形空格深度清洗**：
   从网页、PDF 或富文本编辑器复制的代码或普通文本中，经常夹带网页专用的不换行空格（NBSP，`\u00A0`）和行尾无意义的空白字符，以及 Windows/Unix 混合的换行符（`\r\n`）。这些隐形字符在代码执行时会导致莫名语法报错，在 Markdown 里可能造成多余换行。需要纯函数彻底标准化。

## 决策与落地
1. **Markdown 表格列对齐批量转换引擎 (`alignMarkdownTableColumns`)**：
   - 纯函数实现，提取 Markdown 表格的分隔线行，根据传入的全局对齐方式（`"left" | "center" | "right"`）或每列数组批量更新列对齐指示器；
   - 严格保护表格表头、数据行与非表格内容不受影响；
   - 动作菜单接线「📊 批量转换表格列居中对齐并复制」与「📊 批量转换表格列靠右对齐并复制」，表单格式栏接入「✦ 表格居中」与「✦ 表格右对齐」。
2. **文本字段定长补齐截断引擎 (`padOrTruncate`) 与 `{{xlc:pad}}` 动态宏**：
   - 纯函数实现，支持指定目标字符宽度与对齐方向（`left`, `right`, `center`），支持自定义填充符与截断省略号，精准计算 CJK 双倍字宽；
   - 扩展动态宏体系 `{{xlc:pad|10|hello}}`、`{{xlc:pad:right|8|123|0}}`、`{{xlc:pad:center|10|test}}`；
   - 动作菜单接线「📏 定长宽度补齐或截断并复制」，表单格式栏接入「✦ 定长补齐」，表单变量栏补充 `{{xlc:pad|10|hello}}`。
3. **多行文本行尾空格与 NBSP 隐形空格深度清洗引擎 (`sanitizeLineEndingsAndSpaces`)**：
   - 纯函数实现，将 `\u00A0` 转换为标准 `\u0020`，剥离多行文本每行的行尾空格与制表符，并将换行符统一规范化为 `\n`；
   - 动作菜单接线「🧼 清理行尾空格与 NBSP 隐形空格并复制」，表单格式栏接入「✦ 清洗空格」。
4. **自动化门禁与双向严格负向验证**：
   - 新增 `tests/r354-tablealign-padtruncate-and-linesanitize.test.cjs` 专项测试；
   - 负向突变 87 破坏 `padOrTruncate` 输出，突变 88 破坏 `sanitizeLineEndingsAndSpaces` 对 NBSP 的替换，两项负向测试均被精确拦截；
   - 源码恢复后复验全绿通过，单元测试总数达到 936/936 项。
