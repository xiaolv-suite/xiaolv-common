# ADR 0141：文本字符视觉宽度度量、条件三元求值宏与列表缩进批量升降 (Visual Width Metrics, If Ternary Macro & Shift List Indentation)

## 状态
已接受，T-0505~T-0509（2026-10-29）。

## 背景与上下文
在思源笔记常用内容资产的精细排版、动态模板逻辑分支渲染及大纲列表层级整理场景中，存在三类高频实用痛点：
1. **多行中英文案字符视觉宽度与字符类型精准度量**：
   在设计控制台边框、对齐表格、徽标宽度或卡片排版时，纯字符计数（`length`）无法反映实际占用列宽（一个汉字占 2 列，Emoji 占 2 列，ASCII 占 1 列）。需要纯函数返回精准的视觉宽度（Visual Width）、总字符数、汉字数及 ASCII 字符数；
2. **模板变量动态条件判断与三元表达式引擎（`{{xlc:if}}` 动态宏）**：
   在复用带参模板（如请假单、邮件模板、发布日志）时，某些段落需要根据变量值动态渲染（如 `count > 0` 呈现待办详情，否则呈现已完成；或 `role == 'admin'` 呈现管理员通道）。传统做法必须依赖外部脚本或重复定义两套模板，需要安全、零 eval 的条件三元判断宏；
3. **列表项与多行文本缩进层级批量升降**：
   用户在整理多级嵌套任务或思维导图大纲时，常常需要对选中的多行列表项批量向右加深缩进（如增加 2 空格或 4 空格）或向左提升缩进（底限 0），且必须严密保护非列表正文行与空行。

## 决策与落地
1. **文本字符宽度度量与对齐占位计算引擎 (`measureVisualWidth`)**：
   - 纯函数实现，严密执行 Unicode 码点遍历，计算 CJK 汉字双倍列宽；
   - 输出包括 `visualWidth`, `charCount`, `cjkCount`, `asciiCount` 4 项维度指标；
   - 动作菜单接线「📏 度量文本视觉宽度与字符统计」，表单格式栏接入「✦ 统计字宽」。
2. **动态布尔条件求值与三元表达式引擎 (`evaluateTernaryCondition`) 与 `{{xlc:if}}` 动态宏**：
   - 纯函数实现，零 eval，安全支持数值比较（`>`, `>=`, `<`, `<=`, `==`, `!=`）、字符串相等与子串包含匹配（`contains`），以及非空/布尔 Truthy 判定；
   - 扩展动态宏体系 `{{xlc:if|10 > 5|大|小}}`、`{{xlc:if|role == 'admin'|管理员|普通用户}}`、`{{xlc:if:not|true|开|关}}`；
   - 表单变量栏补充 `{{xlc:if|1 > 0|真|假}}`。
3. **列表项与多行缩进批量升降引擎 (`shiftListIndentation`)**：
   - 纯函数实现，按正则精确匹配列表标记（`- `, `* `, `+ `, `1. `），按指定 `deltaSpaces` 增减缩进空格；
   - 动作菜单接线「➡️ 列表项层级缩进 (+2格) 并复制」，表单格式栏接入「✦ 列表缩进+2」。
4. **自动化门禁与双向严格负向验证**：
   - 新增 `tests/r367-visualwidth-ifmacro-and-shiftindent.test.cjs` 专项测试；
   - 负向突变 113 破坏字宽度量输出，负向突变 114 破坏条件判断逻辑，两项负向测试均被精确拦截；
   - 源码恢复后复验全绿通过，单元测试总数达到 981/981 项。
