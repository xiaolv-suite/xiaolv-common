# ADR 0135：Markdown代码块语言标识批量补全、宏管道符转义宏与多列网格分栏排版 (Code Fence Lang, Escape Macro & Grid Columns Formatter)

## 状态
已接受，T-0475~T-0479（2026-10-29）。

## 背景与上下文
在思源笔记内容资产的代码整理、嵌套动态宏编排及多行清单排版展示场景中，存在三类高频实用痛点：
1. **Markdown 代码围栏语言标识批量补全与修改**：
   从网络或纯文本编辑器粘贴代码时，代码围栏常呈现为裸代码块（```` ``` ````），导致思源内核无法为其提供准确的高亮渲染和格式化支持。用户需要纯函数一键扫描多行文本中的裸代码块并批量补全语言类型（如 `ts`, `json`, `sql`, `python`），同时严密保护闭合围栏不被污染；
2. **嵌套占位符宏参数中管道符冲突安全转义与反转义**：
   在动态模板的高级嵌套使用中（如在 `{{xlc:regex:...}}` 中使用正则 `a|b`，或在 `{{xlc:template:...}}` 中传入带 `|` 的字典数据），管道符 `|` 与宏自身的分隔符直接冲突导致解析器截断报错。用户需要专门的转义引擎（`\|`）与宏函数 `{{xlc:escape}}` 进行安全的编解码；
3. **多行文本多列网格分栏排版引擎**：
   当文本清单条目较多且单项较短（如姓名列表、标签索引、快捷键清单、ID 列表）时，逐行单列纵向排版会导致文档极其冗长。需要纯函数自动根据 $N$ 列（如 3 列）计算各列的 CJK 视觉宽度，并在行内等宽对齐填充输出。

## 决策与落地
1. **Markdown 代码块语言标识批量添加与修改引擎 (`setMarkdownCodeFenceLang`)**：
   - 纯函数实现，状态机追踪代码围栏开闭状态，只对开始围栏补充或覆盖语言标识，保护闭合围栏；
   - 支持 `overwriteExisting: true` 覆盖已有语言，或默认仅补充裸代码块；
   - 动作菜单接线「🏷 批量为代码块补全 ts 语言高亮并复制」，表单格式栏接入「✦ 补全代码TS高亮」。
2. **占位符宏参数安全转义与反转义引擎 (`escapeMacroPipe`) 与 `{{xlc:escape}}` 动态宏**：
   - 纯函数实现，支持 `escape`（`|` -> `\|`）与 `unescape`（`\|`、`&#124;`、`%7C` -> `|`）；
   - 扩展动态宏体系 `{{xlc:escape|a|b|c}}`、`{{xlc:escape:unescape|a\|b}}`；
   - 动作菜单接线「🛡 转义宏参数管道符 (\|) 并复制」，表单格式栏接入「✦ 转义管道符」，表单变量栏补充 `{{xlc:escape|hello|world}}`。
3. **多行文本基于列宽网格化（多列分栏排版）转换引擎 (`formatTextColumnsGrid`)**：
   - 纯函数实现，支持 CJK 字符双倍字宽计算，多行文本自动按 $N$ 列切分并在列间自动插入补偿空格；
   - 动作菜单接线「📑 紧凑 3 列分栏网格排版并复制」，表单格式栏接入「✦ 3列分栏网格」。
4. **自动化门禁与双向严格负向验证**：
   - 新增 `tests/r361-codefencelang-escapemacro-and-gridcolumns.test.cjs` 专项测试；
   - 负向突变 101 破坏代码块语言设置输出，负向突变 102 破坏管道符转义逻辑，两项负向测试均被精确拦截；
   - 源码恢复后复验全绿通过，单元测试总数达到 962/962 项。
