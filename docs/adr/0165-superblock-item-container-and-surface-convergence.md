# ADR 0165：超级块单容器承载多段正文、界面减法与通用工程门禁（T-0752 ~ T-0755）

- **状态**：已采纳（2026-10-31，v0.10.80）
- **关联任务**：T-0752 ~ T-0755

## 背景与问题

1. **多段正文无法保存（B-006）**：此前条目直接以裸 Markdown 追加到库文档，思源 `appendBlock` 会把多段内容拆成多个顶层兄弟块且响应不保证返回完整子块 ID 清单，`updateBlock` 也只更新首块。为此引入的 `bodyWriteRestriction` 被迫把所有库条目限制为「单行文本或单个完整代码围栏」，导致内置 25 条示例包有 17 条被拒（仅 8/25 可装），真实多段话术与模板均无法保存。
2. **界面表面过度膨胀挤压主操作区**：
   - 新建/编辑表单的变量栏（`.xlc-varbar`）平铺了 217 个宏与格式化按钮，使表单滚动高度膨胀至 2827px，保存按钮被推到视口外 2000px；
   - 条目右键动作菜单（`.xlc-menu`）平铺了约 180 个文本转换项；
   - 主搜索弹窗叠加了 19 个快捷键提示（折成 3 行）、统计指标横带（`.xlc-metrics-strip`，59px）与未限高的 `.xlc-pane-vars`（140px），导致 `.xlc-pane-foot` 的主操作按钮在 100%/125%/150% 视口下均被挤出视口裁切。
3. **测试与门禁自证循环**：截图 Harness 使用独立手写翻译表掩盖了生产语言包缺失键；缺少针对语言键/`%s` 参数、Electron 禁用的 `window.prompt`/`window.alert` 及多缩放视口主按钮可见性的通用门禁。

## 决策與取舍

### 1. 超级块（`{{{row ... }}}`）作为多段条目的唯一顶层物理容器

在隔离思源内核 `v3.8.9` 上对候选方案 A（超级块容器）与方案 B（每条目一子文档）实测对比后，选定**方案 A（超级块容器）**：
- **写入路径（`toItemStorageMarkdown`）**：单行普通文本或单个完整代码围栏保持原块形态（100% 兼容存量条目）；其余多段/列表/引用/表格/混合结构统一包裹为 `{{{row\n...\n}}}` 一次调用 `appendBlock`。真内核实测 `doOperations` 恒只返回 **1 个顶层超级块 ID**（`type: "s"`）。
- **行首变量防误判（`guardEmbedLines`）**：真内核实测发现思源 Markdown 解析器会把行首（含列表/引用前缀后）的 `{{...}}` 解析为 `query_embed` 嵌入查询块并拆碎段落。写入时在非代码行的行首 `{{` 前垫入一个零宽空格 `\u200b`，读回时自动剥离。
- **更新路径属性保持（`updateItemUnlocked`）**：真内核实测发现 `updateBlock` 重建块后块 ID 保持不变，但**会丢失块上的全部自定义属性**。因此在 `updateBlock` 成功后立即重新调用 `setBlockAttrs` 原样补回除 `id`/`updated` 外的全部块属性；已是超级块的条目在单段更新时保持容器形态，避免退化拆块。
- **读回路径（`storedKramdownToBody`）**：剥离宿主为子块生成的 `{: id="..."}` IAL 行、外层 `{{{row ... }}}` 包装、引用块尾随空 `>` 行以及内核在行内反引号两侧注入的 `\u200b`，同时完整保留用户自己编写的无 ID 属性（如 `{: custom-priority="high"}`）与代码块字面量。
- **边界收敛（`itemBodyRestriction`）**：仅拒绝空正文、超长正文及代码围栏外的行首 `{{{` / `}}}`（防止提前闭合超级块容器）；单块原地快编（`omni-search` / `quick-edit`）仍保留 `bodyWriteRestriction` 以免把他人单块拆成多块。

### 2. 界面做减法，恢复主操作区首屏可见

- **工具栏收敛**：`.xlc-varbar` 默认只展示 10 个核心变量按钮，其余约 207 个扩展宏与文本格式化按钮收进可折叠、支持实时关键词搜索的「🛠 文本工具…」抽屉（默认 `hidden`）；
- **动作菜单收敛**：`.xlc-menu` 保留核心动作，将约 180 个文本清洗/转换项收进可搜索的「🛠 文本工具…」入口；
- **主搜索减负**：移除顶部 `.xlc-metrics-strip` 统计横带；顶部快捷键提示从 19 项收敛为 5 项核心键（`Enter`、`Ctrl/⌘+Enter`、`Alt/⌥+1-9`、`Tab`、`Esc`）；限制 `.xlc-pane-vars` 最大高度并配合 `max-height: 620px` 紧凑规则。

### 3. 通用工程门禁替代源码字符串自证

- Harness 直接读取生产 `src/i18n/zh-CN.json`；
- 新增静态契约门禁 `scripts/check-ui-contracts.cjs`（`pnpm run check:ui`）：强制 `zh-CN.json` 与 `en.json` 键集和 `%s` 数量对齐、校验 `src/**/*.ts` 所有 `t(...)` 调用键存在且 `%s` 实参个数匹配、禁止 `window.prompt`/`window.alert`、禁止未转义 `innerHTML` 模板插值；
- 新增视口主按钮门禁 `scripts/check-viewport-actions.cjs`（`pnpm run check:viewport`）：在 `1280×720`（100%）、`1024×576`（125%）、`853×480`（150%）三档视口下实测搜索、新建、首跑引导、发现四个弹窗的主操作按钮均在视口内且中心点 `elementFromPoint` 可点中；
- 剪贴板历史改为默认关闭（`clipboardHistoryEnabled: false`），需用户在设置中主动开启，同时完整保留已有历史数据；
- Dock 侧栏动作复用主搜索的 `executor.run` + `openVariableFillCard` 路径。

## 验证结果

- 隔离思源内核 `v3.8.9` 实测（`scripts/integration-kernel.cjs`）：**33/33 全部通过**，内置 5 套模板包共 43 条（含「常用内容示例」**25/25**）全部写入并逐条回读一致，0 `query_embed` 误判；
- 静态契约门禁 `check:ui` 与视口门禁 `check:viewport`（12/12）均通过破坏性负向注入验证与恢复复验；
- 全仓单元测试 **1172/1172 通过**，交互审计 **79/79 通过**。
