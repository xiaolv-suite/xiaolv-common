# ADR 0100：Markdown 链接提取、确定性文本散列指纹与行前后缀批量添加引擎 (Markdown Links Extraction, Deterministic Hash & Line Affixing)

## 状态
已接受，T-0300~T-0304（2026-10-28）。

## 背景与上下文
在思源笔记常用内容资产层的高频复用与对外分发场景中，用户面临三个典型的文本处理痛点：
1. **多链接资产批量整理提取耗时**：
   技术方案、参考资料或客服文档中常包含大量 Markdown 链接（`[标题](URL)`）、图片链接（`![alt](URL)`）以及裸 HTTP(S) 地址。对外发送或编写总结附录时，用户需要将分散在正文各处的链接一次性提取为规范清单。
2. **文本指纹与版本一致性校验缺乏轻量机制**：
   在编写配置模板、提示词版本记录、接口文档或 SQL 脚本时，用户经常需要生成文本指纹或散列标识符。传统依赖外部 Node/C 库的方案在纯 Web 或移动端环境存在兼容隐患。
3. **多行列表批量规整与包裹繁琐**：
   在将纯文本整理为 Markdown 列表、引用块或 SQL `IN` 查询条件时，用户需要逐行添加前缀（如 `- `、`> `、`'`）与后缀（如 `',`）。

## 决策与落地
1. **Markdown 链接与 URL 批量提取引擎 (`extractMarkdownLinks`)**：
   - 纯函数实现，两阶段精准扫描：第一阶段提取并暂存 Markdown 格式链接与图片，第二阶段提取正文裸 URL 地址并清洗末尾标点符号。
   - 支持按 URL 自动去重（`dedupe: true`），支持仅提取图片（`imagesOnly`）或排除图片（`excludeImages`）。
   - 支持多种输出格式：`list`（Markdown 无序列表）、`urls`（纯链接换行列表）与 `json` 结构化对象数组。
   - 动作菜单接线「🔗 提取链接清单并复制」，表单格式栏接入「✦ 提链接」。
2. **跨平台确定性文本散列与指纹生成引擎 (`generateTextHash`)**：
   - 零外部依赖，纯 TypeScript 实现跨平台标准算法：FNV-1a（32-bit）、DJB2 与 CRC-32。
   - 自行实现 UTF-8 字符串到字节序列的无损转换，确保在不同操作系统与浏览器内核下哈希结果 100% 恒定确定。
   - 支持 8 位十六进制（默认）与 base36 紧凑编码，支持指定截断长度。
   - 扩展动态宏体系：`{{xlc:hash|TEXT}}`、`{{xlc:hash|crc32|TEXT}}` 以及冒号语法 `{{xlc:hash:djb2|TEXT}}`。
   - 动作菜单接线「# 计算散列指纹 (FNV-1a) 并复制」，表单快捷变量栏补充 `{{xlc:hash|文本}}`。
3. **多行文本批量添加行前后缀引擎 (`affixLines`)**：
   - 纯函数实现，支持为多行文本每行添加指定前缀与后缀；
   - 默认忽略空行（`ignoreEmpty: true`），支持行首尾多余空白预清洗（`trimLines`）。
   - 表单快捷格式栏接入「✦ 加列表行」按钮（默认前缀 `- `，支持全文与选区快速转换）。
4. **测试套件与严格双向负向门禁**：
   - 新增 `tests/r326-links-hash-and-affix.test.cjs` 专项测试，覆盖链接提取、哈希算法、行前后缀与占位符宏；
   - 负向违规注入：篡改提取计数与破坏哈希断言均能让测试精准失败拦截；源码恢复后全套 826/826 单测全绿通过。
